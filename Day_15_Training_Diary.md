# Day 15 -- Introduction to Databases, SQL and NoSQL

**Topic Covered:** Database Fundamentals, Relational and Non-Relational
Databases, SQL vs NoSQL and Introduction to MongoDB.

## Daily Training Diary

Today, I learned about the fundamentals of databases and their
importance in backend application development. I understood that a
database is an organized collection of data that allows applications to
store, retrieve, update and manage information efficiently.

I studied the two major categories of databases: **relational databases
(SQL)** and **non-relational databases (NoSQL)**.

I learned that relational databases organize information into tables
consisting of rows and columns. They generally use SQL (Structured Query
Language) to perform database operations and support relationships
between tables through keys. Examples include MySQL and PostgreSQL.

I also learned about NoSQL databases, which support different data
models such as document, key-value, column-family and graph databases.
These databases can be useful when applications need flexible data
structures or particular scaling and access patterns. MongoDB is an
example of a document-oriented NoSQL database.

I compared SQL and NoSQL databases in terms of data organization, schema
structure, relationships, query methods and typical use cases. I
understood that the choice of database depends on application
requirements rather than one database type being suitable for every
situation.

Next, I was introduced to **MongoDB**, a document-oriented NoSQL
database. I learned that MongoDB stores data as documents in BSON
format, which is a binary representation of JSON-like data. Documents
are grouped into collections, and collections are organized within
databases.

## Practical Learning

I explored the basic MongoDB concepts of databases, collections and
documents. I examined how a document can store related information using
fields and values, including nested objects and arrays.

I related these concepts to the Banking Ledger Management System.
MongoDB can store application data in separate collections, such as
users, accounts, transactions and ledger entries. I understood that each
collection would represent a particular type of application record and
that references could be used to associate related records.

## Learning Outcomes

-   Understood the purpose and importance of databases in backend
    development.
-   Learned the differences between relational and non-relational
    databases.
-   Understood the basic concepts of SQL and NoSQL.
-   Gained an introduction to MongoDB and its document-oriented
    structure.
-   Learned the relationship between databases, collections and
    documents.
-   Understood how MongoDB can organize data for the Banking Ledger
    Management System.
